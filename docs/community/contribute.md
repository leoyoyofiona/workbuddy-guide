# 贡献内容

最有价值的贡献不是“我觉得这个功能很好用”，而是一份别人可以复现、核对并继续学习的案例。

## 一个合格贡献的结构

| 部分 | 要提交什么 |
| --- | --- |
| 场景 | 谁要完成什么工作，输入是什么 |
| 步骤 | 从哪个入口开始，每一步做什么 |
| 证据 | 官方 URL、版本、截图或示意图说明 |
| 产物 | 得到什么文件/表格，如何验收 |
| 限制 | 哪些账号、系统、版本或权限未验证 |
| 安全 | 是否已脱敏，是否包含外部连接 |

## 案例：贡献一篇“数据分析”教程

先用脱敏 CSV 跑通三轮分析，提交原始字段说明、指令、产物截图和人工修改点；不要提交真实客户数据。截图上标明版本和日期，不能把第三方教程中的 UI 当作当前 WorkBuddy 证据。

仓库：[leoyoyofiona/workbuddy-guide](https://github.com/leoyoyofiona/workbuddy-guide)
