# 额度、套餐与功能边界

额度信息很容易过时，也可能因地区、账号、企业配置、模型和任务类型不同而变化。学习的目标是掌握核验方法，不是背一个数字。

## 案例：开始一次长调研前先做额度记录

1. 打开当前官方产品页或客户端的套餐/额度入口。
2. 记录地区、账号类型、页面日期和原文提示。
3. 记录预计使用的模型、文件数量、连接器和输出格式。
4. 把可能消耗 Credits 或触发付费的步骤列出来。
5. 用小样例先运行，确认实际提示后再扩大范围。

## 记录表

| 字段 | 填写内容 |
| --- | --- |
| 核验日期 | YYYY-MM-DD |
| 地区/账号 | 个人、企业或其他当前类型 |
| 来源 | 官方 URL、客户端入口或提示截图 |
| 任务 | 例如调研、PPT、数据分析 |
| 限制 | 文件、模型、调用、存储或平台条件 |
| 不确定项 | 当前页面没有明确说明的部分 |

## 不要这样写

“WorkBuddy 永久免费”“所有功能不限量”“某功能一定支持某格式”。

## 建议这样写

“截至核验日期，官方页面/客户端显示……；不同账号、地区和版本可能不同，请以当前提示为准。”

<div class="wb-callout"><strong>完成标准：</strong>读者能复现你的核验时间、账号和来源；如果额度变化，也能知道该改哪一条记录。</div>
