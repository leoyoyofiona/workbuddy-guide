# 学习路线

不要从“把所有按钮都点一遍”开始。用一个真实任务贯穿四个阶段：先让 WorkBuddy 交付一个小结果，再把过程沉淀为模板，最后扩展到多专家协作。

## 四阶段路线

| 阶段 | 目标 | 推荐页面 |
| --- | --- | --- |
| 认识 | 完成安装，知道文件、对话与产物在哪里 | [安装](/start/install)、[界面](/start/chat) |
| 交付 | 跑通一个可检查的任务 | [第一个任务](/start/first-task)、[产物](/start/outputs) |
| 复用 | 用 Skills、提示词和工作流减少重复沟通 | [Skills](/start/skills)、[提示词](/advanced/prompting) |
| 放大 | 让多个专家并行协作，完成研究和业务交付 | [专家协作](/advanced/experts)、[实战配方](/recipes/research) |

## 推荐顺序

1. [安装与账号准备](/start/install)
2. [跑通第一个任务](/start/first-task)
3. [理解文件与产物](/start/files)
4. [学会写可执行指令](/advanced/prompting)
5. 任选一个[实战配方](/recipes/research)

## 学完的验收标准

- 能独立描述一个有目标、有输入、有约束、有交付格式的任务。
- 能检查 WorkBuddy 的来源、产物和失败原因。
- 能把一次成功任务改写成下次可复用的模板。
- 能明确区分官方能力、本机实测和通用方法。
