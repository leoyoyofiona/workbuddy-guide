# 跑通第一个任务

第一个任务不要选“写一份完整市场报告”。选择一个输入明确、结果容易检查、失败成本低的任务：把会议记录整理成三列表格。你要练的是如何交代任务，而不是测试模型会不会猜。

<figure class="wb-figure"><img src="/images/workbuddy/plan-loop.svg" alt="WorkBuddy 任务闭环示意图，从目标、输入、计划、执行到验收和复用"><figcaption><strong>案例地图：</strong>本页的会议记录练习对应闭环中的“目标—输入—计划—执行—验收—复用”，每一步都要留下可检查的证据。</figcaption></figure>

## 任务材料

准备一段 10—20 行的脱敏会议记录，例如：

```text
周一增长例会：小林在周三前补充落地页数据；设计组下周一给出两个首屏版本；预算是否增加需要王经理确认。下次会议讨论渠道归因。
```

## 第一次指令：只要求计划和缺口

```text
请先不要生成最终表格。先复述任务目标，列出你需要确认的字段、可能存在的不确定信息，以及准备采用的输出结构。只使用我提供的会议记录。
```

检查它是否识别出“预算是否增加需要确认”，而不是把它写成已经决定。

## 第二次指令：执行并锁定格式

```text
请把上面的会议记录整理成 Markdown 表格，列为：事项、负责人、截止时间、下一步。
规则：
1. 只使用原文信息；没有写明的负责人或时间填“待确认”；
2. 每一行保留对应的原文短句，便于我回溯；
3. 表格后列出 3 个需要我补充的问题；
4. 不要把建议写成已完成事项。
```

## 逐项验收

| 检查 | 通过样子 | 失败样子 |
| --- | --- | --- |
| 事实 | 每行都能回到原文 | 出现原文没有的数字或负责人 |
| 不确定性 | “预算是否增加”仍待确认 | 被改写成已批准 |
| 格式 | 列名、行数、顺序符合要求 | 多出无法解释的列 |
| 可用性 | 可复制到文档继续编辑 | 只有一段散文总结 |
| 追问 | 问题能帮助补齐任务 | 泛泛地说“请提供更多信息” |

## 复盘并改一个变量

把本次记录保存为“输入—指令—产物—人工修改—失败点”。第二次练习只改一个变量，例如把受众从“内部团队”改成“客户”，观察语气和信息取舍发生了什么变化。

<div class="wb-lesson"><h3>练习升级</h3><p>让 WorkBuddy 输出一份“原文证据表”和一份“行动清单”，再人工比较两份结果是否引用了同一组事实。你能解释差异，就完成了第一轮学习。</p></div>

<div class="wb-callout"><strong>验收：</strong>你能拿到一份可复制的 Markdown 表格，指出至少一处需要人工确认的内容，并能用同一模板处理第二段会议记录。</div>
