# 安装与账号准备

安装不是“把应用打开”这么简单。第一次使用前要同时确认来源、设备政策、账号状态和文件边界，否则后面所有排错都会缺少基线。

## 1. 从官方入口确认平台

打开[WorkBuddy 官方产品页](https://copilot.tencent.com/work/)，确认当前提供的下载方式、适用平台和登录入口。不要从搜索结果中的第三方安装包开始，也不要把 CodeBuddy IDE 的下载页当作 WorkBuddy 下载页。

| 检查项 | 你要记录什么 | 为什么重要 |
| --- | --- | --- |
| 来源 | 页面 URL、访问日期 | 后续核验安装包和版本 |
| 系统 | macOS/Windows、芯片或架构 | 解释安装失败和界面差异 |
| 账号 | 个人/企业、登录方式 | 影响可见功能与权限 |
| 网络 | 公司代理、VPN、可访问域名 | 解释加载和连接失败 |
| 设备政策 | 是否允许 AI 工具、文件上传、外部连接 | 避免绕过组织审批 |

## 2. 安装后做一次“空载检查”

1. 启动客户端，记录右上角或设置页显示的版本号。
2. 不上传文件，先确认能进入任务/对话入口。
3. 输入无敏感信息的测试指令：`请把 1、2、3 按升序列成表格。`
4. 观察是否出现任务状态、过程信息和结果区域。
5. 退出并重新打开，确认是否仍能进入同一工作区或任务列表。

## 3. 先建立安全基线

<div class="wb-lesson"><h3>第一次测试只用公开或虚构材料</h3><p>例如“把以下三条公开活动信息整理成表格”。不要使用客户合同、身份证、未公开财务数据或内部聊天记录。能否上传某类文件，要看组织政策、服务条款和客户端实际提示，不能由本指南替你批准。</p></div>

## 安装验收表

| 项目 | 通过条件 | 未通过怎么办 |
| --- | --- | --- |
| 来源 | 能回到官方产品页 | 删除未知安装包，重新从官方入口开始 |
| 版本 | 已记录版本和日期 | 在设置/关于页面查找，找不到就截图反馈 |
| 登录 | 能进入任务入口 | 检查网络、企业账号和官方支持入口 |
| 测试任务 | 得到可读结果 | 记录错误文本，不要连续重复点击 |
| 安全 | 未上传敏感材料 | 先使用脱敏样例重新测试 |

<div class="wb-callout"><strong>完成标准：</strong>你有一条官方来源记录、一个客户端版本号、一条无敏感信息的成功测试结果，以及一份“哪些材料不能上传”的清单。</div>
