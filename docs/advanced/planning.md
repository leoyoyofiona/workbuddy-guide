# 任务拆解与计划

复杂任务失败，常常不是因为不会写，而是因为范围、输入和验收没有分开。先要求计划，再决定是否执行。

## 案例：做一份竞品简报

目标是给产品评审会准备一页简报，不是“把网上所有信息都搜一遍”。

```text
先不要写正文。请为“国内协作工具的文件评论功能”制定研究计划：
范围：2025-01 至今，选择 3 个公开可核验产品；
步骤：资料清单 → 统一比较维度 → 证据表 → 一页摘要；
每步说明输入、产物、风险和完成标准；
遇到来源无法打开、口径不一致或需要登录时暂停提问。
```

## 计划验收表

| 步骤 | 合格计划 | 不合格计划 |
| --- | --- | --- |
| 资料清单 | 有 URL、日期、筛选理由 | “搜索相关资料” |
| 比较维度 | 每个产品使用同一套字段 | 每个产品写不同重点 |
| 证据表 | 结论能回到原文 | 只有观点没有依据 |
| 摘要 | 一页一个结论 | 直接复制长报告 |
| 风险 | 写出缺口和暂停点 | 默认所有资料都可用 |

## 执行时如何控制范围

每完成一个阶段，用一句话确认：“我看到的产物是……；接下来会……；仍缺少……”。如果下一步要发送邮件、修改文件或产生费用，重新确认权限。

<div class="wb-lesson"><h3>练习：反向拆解</h3><p>找一份你最近完成的报告，把它倒推成 5—7 个步骤。每步写出输入、产物和验收。若一个步骤仍包含“收集、判断、写作”三种动作，就继续拆分。</p></div>
