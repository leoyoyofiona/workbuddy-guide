# 常见失败与排查

排错的目标不是“赶快重试”，而是用最少变量复现问题。每次只改变一个条件，并保留原始错误。

## 案例：任务一直显示执行中

1. 记录任务标题、开始时间、客户端版本和系统。
2. 查看是否有新的中间产物或错误提示。
3. 不要立刻上传同一份敏感文件重试。
4. 用一条最小指令验证网络和账号：`只返回 1+1 的结果，不读取文件。`
5. 若最小任务成功，逐步加回文件、Skill 和连接器，找出第一个失败变量。

## 现象—证据—动作表

| 现象 | 先收集 | 下一步 |
| --- | --- | --- |
| 没有响应 | 网络、登录、版本、任务时间 | 先跑最小无文件任务 |
| 缺少材料 | 文件名、引用范围、权限提示 | 只引用一个小文件测试 |
| 产物打不开 | 格式、下载状态、文件名 | 要求先输出纯文本索引 |
| 结果不准 | 来源、时间、口径、原文 | 加入证据表和待确认项 |
| 连接失败 | 连接器、授权时间、权限 | 降级为只读或重新授权 |

## 最小复现模板

```text
环境：macOS/Windows，WorkBuddy 版本：
入口：从哪里进入任务：
最小输入：不含敏感信息的 1—3 行文本：
步骤：1… 2… 3…
实际结果：完整错误文本或状态：
期望结果：
已尝试：只列出改变过的变量：
```

## 什么时候停止排查

出现权限不明、数据可能外泄、重复扣费、自动发送、不可逆写入或无法恢复的文件损坏时，停止继续实验，转交管理员或官方支持。

<div class="wb-callout"><strong>完成标准：</strong>别人拿到你的记录，不需要访问内部文件，就能复现或判断问题属于环境、输入、权限、版本还是服务状态。</div>
